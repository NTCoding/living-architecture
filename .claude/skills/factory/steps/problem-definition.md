# Problem definition

Draft `problem-definition.md` for an idea that has just started planning.

## What the document must answer

- What the problem is, in the words of the person who has it.
- Who has it, and what it costs them today.
- What we already do about it, and why that isn't enough.
- What "solved" looks like, as something you could check.
- What is out of scope, so the next steps don't drift.

## Checklist before you tell Nick it is ready

- [ ] Every claim about today's behaviour quotes the code or the file it comes from.
- [ ] No solution is named yet. This step is about the problem.
- [ ] Each open question is a `:::decision` block.
- [ ] The document has no paragraph longer than 4 sentences.
